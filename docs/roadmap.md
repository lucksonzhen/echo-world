# 开发路线图与待办

基线：Android **1.6.11 / code 19**，代码标签 `v1.6.11-preview.1`，原有 APK 与标签保留。本文整理接下来要做的工作，不代表功能已经实现；任务均未指派负责人、未承诺日期。状态更新以任务勾选、对应提交和 [验收记录](acceptance.md) 为准。

## 当前已有与尚未完成

已有：手机直连模型 API、本地唤醒与口令识别、逐项语音引导、底部拨轮、引导页密钥双击粘贴／保存、截图描述、视频抽帧、最近描述重听、可选自动图片和暂停讲解。

未完成：本地视觉大模型推理、完整真机与视障用户验收、所有小红书页面自动识图、自动失败的无视觉反馈、完整可访问性与后台兼容矩阵。已通过的策略或模拟器测试不能把这些事项标为完成。

当前 APK 内置的 Vosk 小语音模型只做语音识别。构建脚本可准备的 Vosk 大语音模型也不是本地视觉大模型；应分开记录体积、效果和验收，不把“更换语音模型”当成离线看图实现。

## 稳定自动识图与接口

### A1：让用户知道为何没有描述

- [ ] 定义用户可理解的状态：已关闭、等待页面停稳、没有找到可定位大图、同图已描述、正在处理、被滚动取消、截图失败、模型失败。
- [ ] 增加“查询当前状态／重听最近错误”的明确入口；自动失败采用可选、限频的短提示，避免静默失效，也避免连续错误覆盖读屏。
- [ ] 为截图、压缩、网络、解析、朗读分别记录耗时和固定错误类别；诊断默认不含 API Key、截图、控件文字、模型原文或其他应用的内容。
- [ ] 导出诊断需本人明确操作，并能预览包含的字段；不增加自动上传遥测。

涉及 `ScreenAssistantService`、`ImageWatchMonitor`、`AssistantApi`、`Narrator`、设置页。验收：用权限关闭、离线、API 拒绝、R04、滚动取消等故障逐一验证；用户能听到状态和下一步，错误不会被播报为识别成功，日志检查无敏感内容。

### A2：小红书图片与 Live 的实际兼容性

- [ ] 在一加 Ace 2 记录实际 Android／ColorOS／读屏／小红书版本，覆盖信息流、笔记详情、多图切换、静态图、Live、评论展开、横竖屏和快速滚动。
- [ ] 以本人同意的非敏感测试内容检查控件类型、可见区域、图片／Live 标签及事件时序，确认是候选未找到、去重误判、取消还是 API 失败。
- [ ] 验证“同区域 Live 只尝试一次”在换图、滑回、窗口切换、失败后手动重试的边界；排查动画事件被当成导航、近似指纹把不同图当成同图的问题。
- [ ] 区分用户翻页与播放器／应用自身动画事件；避免自动滚动不断取消或重新触发。
- [ ] 设计无法定位图片时的明确手动降级入口；如将来增加整屏自动识别，需单独说明上传范围并由用户启用，不能悄悄扩大采集范围。
- [ ] 完成真机基线后再决定是否开放面积、等待与冷却参数；优先给少量易理解的档位，不把调参负担交给首次使用者。

涉及 `ImageWatchPolicy`、`ImageWatchMonitor`、`ScreenshotEncoder`、`ScreenAssistantService`。验收：形成逐场景成功／跳过／失败矩阵和请求次数记录；内容动画不持续重复上传，真实切换能重新描述，关闭模式不读取控件树，滚动／锁屏／切换 App 后旧结果不继续朗读。无法支持的页面明确记录，不宣称全面兼容。

### A3：模型接口的真实画面回归

- [ ] 用公开或明确获准的样例建立静态照片、中文长文字、多图、空白、低清、Live 当前帧等回归集；同时测试小图连接与真实屏幕路径。
- [ ] 分开记录接口地址、模型标识、账号可用能力、HTTP 错误、结束原因和字段失败；不再依据笼统错误建议盲目换地址或模型。
- [ ] 对 Gemini、DeepSeek、OpenAI、兼容接口分别核对官方协议与实际账号能力，记录测试日期；预填名称不等于可用性承诺。
- [ ] 对已知失败补复现测试；继续检查截断、拒绝、超长内容、取消后的晚到结果以及密钥脱敏。不以无限放宽解析规则替代定位问题。

验收：各服务商分别列出真实调用结果与替身测试结果；一次用户请求不会因解析失败静默产生多次收费调用；R04 能指出固定字段与原因。尚无实际密钥或未实测的服务商保持“待验证”。

## 提升交互体验与配置顺畅度

### B1：每一步都清楚，确认只做一次

- [ ] 绘制安装、引导、保存、测试、授权、进入日常使用的状态图，列出每一步进入条件、默认焦点、唯一主要动作、错误和返回路径。
- [ ] 审计重复入口与说明：确认服务商／地址／模型后直接推进，不重新引入“完成本项继续”；将低频设置移到明确的更多设置中。
- [ ] 统一主设置页与引导中的密钥体验。保留“第一次双击粘贴、第二次双击保存”的两次独立动作；覆盖空剪贴板、错误密钥、更换服务商、取消和返回。
- [ ] 验证切到其他应用复制 Key、切回、进程被结束、屏幕旋转、键盘打开／关闭后的进度与焦点；不恢复或朗读未保存的密钥。
- [ ] 模型列表和连接测试增加清楚的等待、成功、失败和取消反馈；重复双击不得重复发请求，失败保留当前步骤与可修改内容。

涉及 `SetupFlow`、`SetupGuideActivity`、`MainActivity`、`KeyPastePage`、`SettingsStore`。验收：逐项回放首次设置、断网再试、返回修改和中断恢复；每次确认最多前进一步，未明确确认不保存、不授权、不发送请求。

### B2：拨轮、排版与读屏协作

- [ ] 建立一致的页面结构：当前步骤、简短说明、当前值／状态、主要操作；统一字号、留白、对比度，验证大字体和显示缩放。
- [ ] 根据真人试用调整拨轮档距、停稳延迟、咔哒声和振动；快速滑动只播报最后停留项，到首尾有明确反馈。
- [ ] 清楚区分无读屏与启用系统读屏时的手势提示，验证焦点落点、子菜单取消、返回及键盘遮挡。
- [ ] 统一引导语音、系统读屏和描述语音的优先级，避免两路同时说话；保留重听、暂停、继续及简短／完整说明的设计。
- [ ] 地址和模型确认时读实际值；可调整冗长地址的播报节奏，但不能只读“确认地址”而不让用户知道确认什么。

涉及 `BottomDial`、`DialPicker`、`SetupGuideActivity`、`MainActivity`、`Narrator`。验收：纯触摸、TalkBack 及目标手机实际读屏分别验证；滑动不误执行、一次双击只执行一次、离开页面无过期播报，大字体不遮挡操作区。

### B3：系统权限的前后衔接

- [ ] 每次跳转系统前，只说清即将找哪个服务／权限、如何返回；回来后重新检测真实状态，成功才推进。
- [ ] 检查一加的已下载无障碍服务、受限设置、麦克风拒绝／永久拒绝、通知设置与后台限制；按实际系统版本写操作路径。
- [ ] 权限被撤销、服务被关闭、TTS 不可用时提供可恢复指引；不把手机自带读屏和本应用服务混为一谈。
- [ ] 只在功能需要时请求权限；不为配置过程启用麦克风，不把可选暂停讲解权限变成基本描述的必选项。

验收：每种权限允许、拒绝、暂缓、从系统返回都能走通；读屏开启时全程可操作，无空白等待、假成功或重复授权循环。

### B4：以视障用户任务测试决定是否顺畅

- [ ] 邀请自愿参加的视障试用者，使用测试账号／无敏感样例完成首次安装配置、改 Key、描述屏幕、重听、停止和故障恢复。
- [ ] 记录是否独立完成、耗时、操作次数、卡住的步骤、需要协助次数与错误恢复路径；反馈记录不包含密钥及私人画面。
- [ ] 先做小规模基线，再按问题严重程度改动并复测同一组任务；完成率与耗时目标在基线后确认。

验收：阻断独立完成的缺陷关闭并复测；产品文案能由首次使用者理解。模拟器 PASS、开发者闭眼操作和合成语音都不能替代此项。

## 本地视觉模型推理

目标是让手机上的视觉模型直接理解截图，区别于当前本地语音识别加云端看图。第一阶段只做**用户主动请求的单张图离线描述／读字**，不同时承诺自动模式、多帧视频和所有机型。

### L1：选型与可行性基准

- [ ] 记录目标一加 Ace 2 的实际内存、可用存储、系统版本和热状态；建立另一档资源更少设备的对照，不只按型号推断可运行性。
- [ ] 至少比较两种候选视觉模型和 Android 推理运行时，核查中文描述、中文 OCR、图像编码器、权重与量化格式、支持算子、许可证、分发条件和维护情况；选型报告附官方来源与日期。
- [ ] 在相同测试集和图像尺寸下比较小／中两档模型与量化策略，分别测 CPU 和设备实际可用的加速路径。GPU／NPU 能否使用必须验证，不能只因手机有硬件就宣称支持。
- [ ] 建立结果表：模型下载／解压体积、冷启动、首句与完整结果延迟、峰值内存、连续运行耗电／温升、中文文字准确性、漏掉关键信息与编造内容的比例。
- [ ] 与当前 API 结果作对照；先产出建议与失败边界，再确定运行时、权重版本和最低配置。若不达标，保留实验状态。

交付：可复现的基准程序、无敏感测试集、实测表、许可证记录和选型决定。具体延迟／质量门槛在基线后确定，不提前承诺“完全离线且流畅”。

### L2：Android 单图推理原型

- [ ] 从 `AssistantApi` 周边抽象统一描述入口，划分云端与本地后端，约定输入图片／问题、进度、结果、不确定性、错误与取消语义；先保留现有云端回归。
- [ ] 接入选定运行时及图像预处理，处理线程、内存、模型加载／卸载、图像缩放、方向和长截图；避免在主线程执行推理。
- [ ] 实现中文简述和读字模式，将结果接入已有 `Narrator`；文本模型如需 OCR 辅助，必须另行实现和测量 OCR，不能假定文本模型能直接看图。
- [ ] 对停止、锁屏、撤销授权、切换画面和新请求实现取消／过期结果丢弃；不支持底层立即中断时，也要停止朗读并回收可释放资源。
- [ ] 对内存不足、模型损坏、图片不支持、推理超时和空结果给出明确提示，不用编造的描述掩盖失败。

交付：无 API Key、断网情况下可完成单张图片描述的实验 APK，以及端到端样例；本地后端不改变已有云端用户配置。

### L3：可访问的模型下载与管理

- [ ] 选择运行时和权重后再设计下载入口，告知大小、可用空间与下载用途，支持本人确认、进度朗读、暂停／恢复和失败重试。
- [ ] 验证 HTTPS 来源、固定版本和 SHA-256；安全解压、原子切换、空间不足和断电恢复，损坏或未完成文件不能当作可用模型。
- [ ] 提供本地模型状态、占用空间、切换、卸载与清理；旧模型仅在新模型通过校验后替换，记录权重与运行时版本便于复现。
- [ ] 下载权重与执行推理分开说明；首次下载可能需要联网，不等于每次本地推理都联网。

交付：用中断、校验失败、空间不足和重启注入测试验证下载流程；盲人能听到当前状态并自行恢复，不需要手动搬文件到隐藏目录。

### L4：本地／云端模式和数据边界

- [ ] 明确显示并朗读当前使用本地还是云端；本地模式不要求填写 API Key，云端模式保留已有连接测试与上传同意。
- [ ] 将“允许本机截图处理”和“允许发送到云端”分别建模与说明，修正当前依赖云端上传同意的入口判断，避免本地模式被迫同意上传。
- [ ] 本地失败只提示本地错误；需要转云端时让用户明确选择，不能自动上传截图兜底。
- [ ] 模型准备好后在断网／飞行模式验证截图、识别、中文朗读；检查 TTS 是否依赖在线声音，并提供离线声音准备指引。
- [ ] 用网络观测确认离线模式无图片、文字和语音外发；升级和模式切换仍保留明确授权边界。

验收：离线推理路径完成且无外发；撤销云端同意后本地功能按其独立授权工作；所有回退均由本人确认，不出现“界面显示本地、实际走 API”。

### L5：端侧试用发布门槛

- [ ] 完成与 L1 相同基准的整包真机复测，覆盖冷启动、连续请求、低内存、过热、低电量和后台切换。
- [ ] 在目标设备连续完成至少 20 次单图任务，记录崩溃、耗时、峰值内存和质量；再进行更长时段试用，不能仅凭一次推理成功发布。
- [ ] 验证可停止、不会读出旧页面结果、不会意外上传、不会因切换模型丢失密钥或配置。
- [ ] 明确列出实测支持机型、模型文件版本、局限和回退到既有 1.6.11 的方式；硬件或质量未达标则继续作为实验版。

只有 L1–L5 有证据后，才规划端侧视频、多图和自动描述。保留云端模式作为用户主动选择，不把它当作隐式兜底。

## 日常使用与后台体验

### D1：语音、等待与打断

- [ ] 区分已听到唤醒词、正在听命令、截图、理解、朗读和失败，用少量一致的音效／短提示表达；允许调节提示频率。
- [ ] 测真人口音、噪声、远场、耳机、外放视频和中英混说；现有 13 段合成语音只作为回归，不代替真人准确率。
- [ ] 测长口令部分识别被提前当成“停止”的边界、外放误唤醒、TTS 自激活、通话抢占与抢占恢复。
- [ ] 研究先读概要、后读细节及流式返回；只有完整可验证的内容才进入播报，取消后不得继续出声。

验收：记录唤醒成功率、误触发、停止响应时间和并发语音冲突；确定基线后再设性能目标，不只凭主观“快一点”验收。

### D2：后台与恢复

- [ ] 在目标厂商系统测灭屏／解锁、重启、进程回收、麦克风权限撤销、通知关闭、断网恢复及电池优化。
- [ ] 引导用户区分“服务已关”“麦克风不可用”和“模型网络失败”；保留可选自动模式的明确开关，不在恢复时擅自开启已关闭模式。
- [ ] 记录待命耗电，按需解释后台设置；不能承诺系统永远不结束进程。

### D3：不依赖视觉定位的物理入口

- [ ] 调研系统允许的耳机／蓝牙按键入口，与播放器、通话和音量键冲突分开测试；先做显式启用的实验入口。
- [ ] 定义单次触发、长按停止、重复按键去抖和状态反馈，保留原有系统功能；不要把配置语音命令重新加回来。

### D4：语音模型与安装体积

- [ ] 分别测 Vosk 小／大语音模型的实际识别收益、解压时间、内存、存储和发热，再决定默认分发策略。
- [ ] 评估按需下载语音模型，复用已验证的模型管理能力；下载失败仍可保留基础可用模式，大小、来源和校验值明确。
- [ ] 区分“语音模型下载”和“视觉模型下载”，让用户知道各自解决什么问题。
